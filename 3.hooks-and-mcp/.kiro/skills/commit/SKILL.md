# commit - 대화형 커밋 가이드

아래 워크플로우를 **순서대로** 실행하세요.

---

## STEP 1: 현황 파악

1. `git status`와 `git diff` (staged + unstaged)를 실행합니다.
2. 변경사항이 없으면 "커밋할 변경사항이 없습니다."라고 안내하고 **종료**합니다.

---

## STEP 2: 변경사항 분류

1. `.kiro/skills/commit/rules.md`를 읽어 커밋 규칙을 로드합니다.
2. **파일 이동을 먼저 찾습니다.** `git status` 는 이동을 삭제(`D`)와 미추적(`??`) 두 줄로 보여줍니다.
   내용이 비슷한 `D`/`??` 쌍이 있으면 이동이므로, **한 커밋으로 묶어 `tidy`** 로 분류합니다.
   쪼개면 이름변경이 영구히 소실됩니다.
3. 각 파일의 diff를 분석하여 커밋 타입별로 분류합니다.
4. 분류 결과를 테이블로 표시합니다:

```
| 파일 | 변경 유형 | 추천 타입 |
|------|-----------|-----------|
| src/utils.ts | 함수 추출 | tidy |
| src/api.ts | 새 엔드포인트 | feat |
```

---

## STEP 3: 분리 판단

- **타입이 1개**면 → STEP 4로 진행
- **타입이 2개 이상**이면:
  - Tidy First 원칙에 따라 `tidy` 커밋을 먼저 하도록 분리 계획을 제안합니다
  - 순서: tidy → feat/fix → test → perf → docs/style/chore
- **단일 커밋이 100줄+**이면 경고를 표시합니다

---

## STEP 4: Staging 가이드

1. 이번 커밋에 포함할 파일 목록을 제안합니다.
2. 사용자에게 확인을 받습니다. 승인 없이 `git add` 를 실행하지 않습니다.
   - "이 파일들을 이번 커밋에 포함할까요?"
   - 선택지: "네, 진행합니다" / "파일을 수정하겠습니다"
3. 승인되면 스테이징합니다.
   - 일반 변경: `git add <파일들>`
   - **이동이 포함된 커밋: 파일을 나열하지 말고 경로째** `git add -A -- <옛 경로> <새 경로>`
     (파일만 나열하면 삭제가 빠져서 이름변경이 `A` 로 떨어집니다)
4. 이동이 있었다면 `git diff --cached --name-status` 로 `R` 이 잡혔는지 확인하고,
   `A`+`D` 로 나왔으면 커밋하지 말고 3번을 다시 합니다.

---

## STEP 5: 커밋 메시지 추천

1. staged된 변경사항의 핵심을 분석합니다.
2. **한글 1줄**, `타입: 설명` 형식의 커밋 메시지를 2-3개 추천합니다.
3. 사용자에게 선택 또는 수정을 요청합니다.
   - 추천 메시지들을 번호로 제시
   - "직접 입력" 선택지 포함

---

## STEP 6: 커밋 실행

1. 선택된 메시지로 `git commit`을 실행합니다.
2. 커밋 성공 여부를 확인하고 결과를 표시합니다.

---

## STEP 7: 반복

1. `git status`로 남은 변경사항을 확인합니다.
2. **남은 변경사항이 있으면** → STEP 4로 돌아갑니다.
3. **없으면** → 완료 요약을 표시합니다:
   - 이번 세션에서 만든 커밋 목록
   - 각 커밋의 타입과 메시지

---

## 주의사항

- Co-Authored-By 헤더는 추가하지 않습니다.
- 커밋 메시지에 영어를 사용하지 않습니다.
- 정리(tidy)와 기능(feat)을 절대 한 커밋에 섞지 않습니다.
